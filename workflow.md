\# CIT 240 GitHub Collaboration Workflow



\## Group 2



This document explains how our team collaborates using Git and GitHub.



\## Team Workflow



1\. Clone the shared repository.



2\. Configure the correct Git username and email.



3\. Update the local main branch.



4\. Create a separate feature branch.



5\. Make changes to the assigned file.



6\. Stage the changes using git add.



7\. Commit changes using git commit.



8\. Push the feature branch to GitHub.



9\. Create a pull request.



10\. Request another member to review.



11\. Review the proposed changes.



12\. Merge the approved pull request into main.



\## Branching Strategy



\- main: Stable version of the project.



\- feature/homepage-message: Jhared's contribution.



\- feature/team-profile: Geronimo's contribution.



\- feature/setup-notes: Jambee's contribution.



\- feature/collaboration-notes: Renalyn's contribution.



\- feature/test-report: Jerwin and Prince's contribution.



\## Pull Request Review Guidelines



Before approving a pull request, reviewers should:



1\. Check the changed files.



2\. Verify the correctness of the content.



3\. Identify possible errors.



4\. Provide constructive feedback.



5\. Approve only when the changes are acceptable.



\## Shared Laptop Guidelines



Each member should use a separate local clone



and their own GitHub account.



Before pushing, verify the correct Git identity



and authenticated GitHub account.



Never share passwords or personal access tokens.



\## Conclusion



GitHub helps our team manage code changes,



track contributions, and collaborate through



branching, commits, reviews, and merges.
